# 概要
- 8bitコンピュータ
- 以下主要コンポーネントがMMUを介して接続されている
    1. CPU(LR35902)           → ゲームのロジック・命令実行
    2. MMU(メモリマップ)       → どのアドレスが何を指すか決める
    3. PPU(LCD コントローラ)   → 画面を描画する
    4. Timer(DIV/TIMA)        → 時間管理・割り込み
    5. ジョイパッド            → 入力
    6. カートリッジ(MBC)       → ROMバンク切替やセーブ管理
- 1フレームの流れ: 
    1. CPU が命令を実行(クロック進む)
    2. 進んだクロックぶん、PPU も進む
    3. 144ライン描画 → VBlank 10ライン
    4. Timer もクロックに応じて進む
    5. 入力があれば Joypad が更新
    6. VBlank 割り込み(画面が切り替わる)

## CPU
1. レジスタ
    - 8bitレジスタ8個(A, F, B, C, D, E, H, L)
        - A: アキュムレータ(計算結果が入る場所)
        - F: Zero, Subtract, HalfCarry, Carry(8bit繰り上がり)の4フラグを持つ。下位4ビットは常に0
        - その他レジスタは値の一次保存やアドレス生成、汎用レジスタ等として用いられる
    - 16bitレジスタ4個(AF, BC, DE, HL)
        - BC: ループカウンタや間接参照
        - DE: コピー処理などに多様
        - AF: ペアとしてはあんまり使われない
        - HL: メモリ参照やインクリメントデクリメント、タイルデータ読み出しなどを担当する
    - その他のレジスタ2個(SP, PC)
        - PC: 普通にプログラムカウンタ
        - SP: 普通にスタックポインタ
    - CPUの作業としてはMMUへの書き込み
        - MMUが上位bitをもとにしてデータの入力先を決定している
    - 命令セット
        1. データ移動(LD)
        2. 算術演算(ADD、SUB、AND、OR、XOR、CP…)
        3. インクリメント/デクリメント(INC/DEC)
        4. ジャンプ / コール / リターン(JP/JR/CALL/RET)
        5. ビット操作(CB-prefix)
    - 割り込み処理
        1. VBlank
        2. LCD STAT
        3. Timer
        4. Serial
        5. Joypad
    - 命令サイクル
        - 1命令あたりの消費サイクル数が異なる
        - また、1ライン = 456クロック, 1フレーム = 154ラインとなっている

2. メモリ読み書き
- MMUがインタフェースとデコーダ的な役割を担っているおかげで、メモリアドレスを指定して読み書きするだけ

3. 命令セット(約500命令)
- AとHLを中心にフラグで分岐し、MMUを介してメモリを操作するだけ
- 7種類に大別できる  
    1. データ転送(LD)
        - LDはロードの意味
        - 50%以上がこれに分類される
        - HLを使ったメモリ読み書きが重要
    2. 算術演算(ADD / SUB / ADC / SBC)
        - Aレジスタを中心にフラグを厳密に管理する
        - Hフラグが重要
    3. 論理演算(AND / OR / XOR / CP)
        - ある意味最も単純
    4. インクリメント・デクリメント(INC / DEC)
        - フラグ更新が必要になる
        - HLの中身を直接インクリメントできる
    5. ジャンプ・分岐(JP / JR / CALL / RET / RST)
        - PCを書き換える命令
        - 条件フラグを用いて分岐処理を行う
        - PCの操作ミスなどに気をつけつつ実装する
    6. ビット操作(CB-prefix)
        - 0xCBを読んだ時点で「次のバイトを別テーブルで引く」という2段階デコードが必要
        - ビットシフトやローテートを行う
        - 命令テーブルが2つ必要
    7. CPU制御(HALT / STOP / EI / DI / NOP)
        - とりあえずは簡易実装

4. 割り込み
- 画面の描画タイミング、時間経過、ボタン入力などで用いる
- 割り込みを管理するレジスタ
    - IE (0xFFFF): Interrupt Enable: どの割り込みを受け付けるか
    - IF (0xFF0F): Interrupt Flag: どの割り込みが発生したか
    - IME: Interrupt Master Enable: 割り込みを今受け付けて良いか(割り込み許可)
- 割り込みが起きる条件
    1. ハードウェアがIFビットを立てる
    2. ROMがIEの該当ビットを立てる
    3. CPUのIMEが1である
- 5種類の割り込みについて
    1. VBlank(0x40)  : 0ビット目。PPUが発生させ、画面更新に用いる
    2. LCD STAT(0x48): 1ビット目。PPUが発生させ、スクロールや描画の同期に用いる
    3. Timer(0x50)   : 2ビット目。Timerが発生させ、ゲームの進行速度管理に用いる
    4. Serial(0x58)  : 3ビット目。通信モジュールが発生させ、あんまり使わない
    5. Joypad(0x60)  : 4ビット目。入力モジュールが発生させ、ボタン押下で利用される
- 割り込み発生の流れ
    1. IMEを0にして割り込みを禁止する
    2. PCをスタックへプッシュして現在のプログラム位置を保存
    3. 割り込みベクタにジャンプ
    4. 割り込み処理が終了後、PCをポップしてIMEを1にする
- その他特殊な挙動について
    - EI(割り込み許可)は1命令分遅延してから有効になる
    - DI(割り込み禁止)は即有効
    - HALTはIME=0 かつ IF=1 のときに特殊挙動を起こす(バグ？)

5. クロック(タイミング)
- GB内の時間全てを管理しており、ハードウェア内の同期を管理している
- GBは60FPSで1フレームあたり154ライン、1ライン456サイクル
    =>　456 cycles × 154 lines = 70224 cycles  
    1フレームあたり70224cycle分の処理をして画面1枚を更新する
- GBの命令セットでは命令ごとに消費するクロック数が異なる


## MMU
- CPUが指定したアドレスに対して、どのハードウェアへのアクセスかを判定し、そのハードへ読み書きを行う
    0x0000–0x3FFF  固定ROMバンク0(カートリッジ)  
    0x4000–0x7FFF  切り替えROMバンク(MBC1など)  
    0x8000–0x9FFF  VRAM(背景・タイル)  
    0xA000–0xBFFF  外部RAM(セーブデータ)  
    0xC000–0xDFFF  WRAM(作業メモリ)  
    0xE000–0xFDFF  Echo RAM(C000–DDFFの写像)  
    0xFE00–0xFE9F  OAM(スプライト)  
    0xFEA0–0xFEFF  使用不可領域  
    0xFF00–0xFF7F  I/Oレジスタ(PPU、Timer、Joypad など)  
    0xFF80–0xFFFE  HRAM(高速RAM)  
    0xFFFF         IE(割り込み許可)  
- 例えば write(0x2000, 0x03)という命令が来ると以下のような処理を行う
    - 0x2000 はROMバンク切替領域
    - これは MBC1 の制御レジスタ
    - よって「ROMバンク番号を3に切り替える」

## PPU
- 画面に 160×144 ピクセルの絵を、タイルとスプライトの情報から生成する
- クロックはCPUと同じ
- 処理は1ラインごとに行う
- 処理が終わるとVBlank割り込みによりCPUに完了を伝える
- 1ピクセルあたり4階調、つまり4色使える
- VRAM(0x8000〜0x9FFF)
    - 各タイル8×8ピクセルで、16バイト
    - タイル番号(0〜255)を並べた32×32のマップ
    - 32×32タイル = 256×256ピクセルの大きな背景を持つ
    - そこから一部(160×144領域)を切り出して表示しているイメージ
- OAM(Object Attribute Memory, 0xFE00〜0xFE9F)
    - スプライト(OBJ)の情報が40個ぶん入っている
    - 1スプライト: 4バイト
        - X, Y座標+タイル番号+属性データ
    - ハードウェア制限により、1ラインあたり10個のスプライトを表示可能
- LCDC(0xFF40): PPUのメイン制御を行うレジスタ
    0. BG表示 ON/OFF
    1. OBJ サイズ(8×8 or 8×16)
    2. OBJ ON/OFF
    3. BG タイルマップ選択
    4. BG/ウィンドウのタイルデータ領域選択
    5. ウィンドウ表示 ON/OFF
    6. ウィンドウタイルマップ選択
    7. LCD 表示 ON/OFF
- STAT(0xFF41): ステータス&割り込み制御
    - PPUの状態やLY==LYC比較などを持つ
    - 今回の場合はあまり強く意識しなくてもOK
- SCY/SCX(0xFF42/0xFF43): 背景スクロール
    - 背景マップ(256×256)のどの位置を画面左上にするかを決めるオフセット
    - SCY: 縦スクロール量(0〜255)
    - SCX: 横スクロール量(0〜255)
- LY/LYC(0xFF44/0xFF45)
    - PPU ControllerがラインごとにLYを更新し、必要ならLY == LYCでSTAT割り込みを起こせる
    - LY: 現在のライン番号(0〜153)
    - LYC: 比較対象のライン番号
- BGP/OBP0/OBP1(0xFF47/0xFF48/0xFF49)
    - BGP: 背景/ウィンドウ用パレット
    - OBP0/1: スプライト用パレット
    - 実際: 2bit→実際の4階調への対応を指定するもの
    - エミュレータでは: 
        - 内部では 0〜3 値を保持
        - 描画直前(SDL出力)で RGBA にマッピング
- WY/WX(0xFF4A/0xFF4B)
    - ウィンドウの表示位置(上端・左端)
    - ウィンドウ機能(LCDC のビット5)とセットで使われます
    - テトリスレベルでは後回しでOK
- PPUの動作モード
    - PPU Controllerは、CPUの進めたcycle数を受け取って以下のステートマシンを進める
        - Mode2: OAM検索(80cycles)  
        - Mode3: VRAM転送(172cycles)  
        - Mode0: HBlank(204cycles)  
        - Mode1: VBlank(456cycles*10ライン)  
    - 表示ライン0〜143で Mode2→3→0を繰り返す
    - ライン144〜153は全てMode1(VBlank)
- ライン描画のフロー
    1. そのラインに対応する背景マップ上のy値(bg_y)を計算する
    2. そのbg_yが属するタイル行を求める
    3. x = 0〜159の各ピクセルについて
        - bg_x = (x+SCX)%256
        - tile_col = bg_x/8
        - 背景マップから(tile_row, tile_col)のタイル番号を読む
        - VRAMからタイルデータを取り出し、bg_y%8行目、bg_x%8列目の2bitを読む
        - その0〜3の色インデックスをLineBufferに書き込む
    4. LineBuffer を FrameBuffer[LY] にコピー


## Timer
- CPUのクロックをもとに、ゲームが使える時間カウンタを提供する装置
- TimerはCPUのcycle(t-cycle)に対して動く => CPUが命令を実行して返すサイクル数に応じて進む
- Timerの構成要素
    - DIV(FF04) : 16kHzのフリーランニングカウンタ
        - DIVはCPUクロックの1/256の速度でカウントアップする  
          => CPUクロックが4,194,304Hzに対し、DIVは16,384Hz
        - DIVに書き込み(write)すると0にリセットされる
        - TIMAのクロック決定に内部で使われる
    - TIMA(FF05): Timerカウンタ(オーバーフローで割り込み)
        - TIMAはTACレジスタの設定に応じて一定周期で加算されるカウンタ
        - TIMAが0xFFから0x00にオーバーフローすると以下の挙動
            1. TIMAはTMAの値をロード
            2. Timer割り込みを発生
        - TIMAはゲーム通知の定期タイマーイベントのトリガーとして機能する
    - TMA(FF06) : TIMAのリロード値
        - TIMAのオーバーフロー時にTIMAをリセットするための値
    - TAC(FF07) : Timer制御(有効/無効 + クロック選択)
        - TIMAが増える周期(CPUクロック何サイクルごとにインクリメントするか)を決める
        - bitの選択によって意味が変わる
            - 0-1: 入力クロックの選択
                - 00: 入力クロック=4096Hz  , CPUサイクル数=1024cycles
                - 01: 入力クロック=262144Hz, CPUサイクル数=16cycles
                - 10: 入力クロック=65536Hz , CPUサイクル数=64cycles
                - 11: 入力クロック=16384Hz , CPUサイクル数=256cycles
            - 2  : タイマーのON/OFF

## Input
- 0xFF00番地の1バイトで8つのボタン入力全てを表現する
- GBにおけるボタンは8個(方向キー4つ+A,B,Start,Select)
- 8bitのうち6bitだけ意味がある(ハードの仕組み的にモードで実装されている)
    0. Down/Start
    1. Up/Select
    2. Left/B
    3. Right/A
    4. P14(ボタンモード)
    5. P15(方向キーモード)
    6. 未使用
    7. 未使用
- どのモードかをP1レジスタに設定後、P1の下位4bitを返す
- GBの場合は0のときON(押されたら0になる)
- ボタンが押されたらIF(0xFF0F)のbit4が立ち、割り込み発生
    1. SDLなどでkey-downを検出する
    2. Joypadの該当フラグをTrueにする
    3. IFのbit4を立てる
    4. CPUが割り込みを処理できるなら0x60にジャンプ

## Bus
- MMUがアドレス空間の分裂というメモリマップのルールを定めている
- 一方でBusは実際のインスタンスに対して処理を振り分ける具体的な配線　　
　=>　つまり実質的なインタフェースとしてCPUはBus経由でしかメモリに触らない
